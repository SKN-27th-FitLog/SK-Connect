# 프론트엔드 버그 수정 및 개선 계획

## 1. 개요
- **목적:** 프론트엔드 앱의 동작을 확인하고 발견된 문제(버그) 사항을 추적 및 수정하기 위한 문서입니다.
- **진행 원칙 (중요):**
  1. **수정 범위:** 모든 버그 수정은 `front/src` 폴더 내부의 코드에만 적용합니다.
  2. **프론트엔드(`front/src` 내) 이슈:** 원인 분석 및 수정 계획을 세운 뒤 **사전 확인 후** 수정을 진행합니다.
  3. **그 외 영역(`front/src` 외부) 이슈:** 직접 수정하지 않고 발생하는 **현상과 문제점만 기록(모음)** 해둔 뒤 다음으로 넘어갑니다.
- **진행 방식:** 앱의 각 기능 및 동작을 확인한 후, 위의 원칙에 따라 이 문서에 기록하고 계획을 수립하여 차례대로 진행합니다.

## 2. 동작 확인 및 문제 사항 기록

### 2.4. 게시글 생성 시 카테고리(cd_table) 값 표시 누락 원인 분석
- **예상 동작:** 게시글 생성 화면에서 선택한 카테고리 값이 백엔드로 전달되어 저장되고, 게시글 목록(PostCard) 및 상세 화면에 해당 카테고리명이 표시되어야 함.
- **실제 동작 (문제점):** 카테고리를 선택하고 글을 작성해도 목록에서 카테고리 이름이 표시되지 않음.
- **원인 분석:**
  1. **프론트엔드 UI 누락:** `front/src/components/post/PostCard.js` 컴포넌트 내부 코드를 확인해본 결과, `post.title`, `post.content`, `post.author` 등은 렌더링하고 있으나 카테고리(`post.category`)를 화면에 표시해주는 UI 코드가 아예 존재하지 않음.
  2. **백엔드 저장/반환 오류 (외부 이슈):** 로컬 터미널의 API 응답 로그를 확인한 결과, 프론트에서 `{ post_cd: "CA02" }`로 정상 전송하였음에도 백엔드의 생성 응답에서 `"post_cd": null`로 반환되고 있음. 또한 목록 응답(`"cd_table": null`)과 상세 응답(`"category": null`) 모두에서 카테고리 데이터를 반환하지 못하고 있음.
- **수정 계획:**
  1. **프론트엔드 (진행 가능):** `PostCard.js` 파일과 상세 화면(`PostDetailScreen.js`)에 카테고리를 렌더링해주는 UI 요소를 추가.
  2. **백엔드 (외부 이슈로 기록):** 백엔드에서 `post_cd`를 DB에 정상적으로 Insert 하고, 목록/상세 조회 시 JOIN을 통해 카테고리 정보를 제대로 반환하도록 백엔드 수정이 필요하다는 점을 기록.

### 2.3. PostCreate(게시글 작성) 화면 헤더 고정 및 뒤로가기 버튼 개선
- **예상 동작:** 게시글 작성 화면의 헤더가 홈이나 상세 화면과 동일한 높이에 위치해야 하며, 뒤로가기 버튼의 클릭 영역이 충분히 넓어야 함.
- **실제 동작 (문제점):** 헤더가 전체 스크롤 뷰 안에 포함되어 있거나 상단 여백 설정이 달라 홈 화면의 "SK Connect"와 위치가 맞지 않고, 높이가 다르게 표시됨.
- **원인 분석:**
  1. `PostCreateScreen.js`에서 헤더 부분(`<Text style={styles.screenTitle}>게시글 작성</Text>`)이 `<ScrollView>` 내부에 있었음.
  2. `postCreateStyles.header`의 높이(`height`)와 여백이 고정되어 있어 상단 레이아웃과 일치하지 않음.
- **수정 계획:**
  1. **헤더 고정 및 뒤로가기 추가:** `PostCreateScreen.js`의 헤더를 스크롤 밖으로 분리하고 `<TouchableOpacity>`를 사용해 뒤로가기 기능(`navigation.goBack()`)과 `hitSlop`을 적용한 헤더로 교체.
  2. **헤더 스타일 맞춤:** `postStyles.js` 내 `postCreateStyles.header`의 높이 고정을 해제하고 `paddingTop`과 `paddingBottom`을 상세 화면과 동일하게 맞춤.

### 2.2. PostDetail(게시글 상세) 화면 상단 헤더 고정 및 터치 영역 확장
- **예상 동작:** 상세 화면에서 스크롤을 내려도 상단에 '‹ 게시글' 헤더가 고정되어 있어야 하며, '뒤로가기' 클릭을 쉽게 할 수 있도록 '게시글' 텍스트까지 터치 영역이 확장되어야 함.
- **실제 동작 (문제점):** 헤더가 `ScrollView` 내부에 포함되어 있어 화면을 스크롤하면 같이 위로 올라가버림. 또한, '‹' 기호 부분만 터치가 가능해 클릭 범위가 너무 좁음.
- **원인 분석:** 
  1. `PostDetailScreen.js`에서 `<View style={styles.header}>`가 `<ScrollView>` 태그 내부에 위치해 있음.
  2. `TouchableOpacity`가 `<Text style={styles.backButton}>‹</Text>`만 감싸고 있어 터치 영역이 제한됨.
- **수정 계획:**
  1. **헤더 고정:** `<View style={styles.header}>`를 `<ScrollView>` 밖(상단)으로 빼내어 화면 상단에 고정되게 위치 변경.
  2. **터치 영역 확장:** `<TouchableOpacity>`가 '‹' 기호뿐만 아니라 '게시글' 텍스트(`<Text style={styles.headerTitle}>`)까지 모두 감싸도록 수정하고, 클릭 영역(`hitSlop` 및 `padding`)을 충분히 부여.

### 2.1. 전체 화면(네비게이터) 상하단 여백 부족 문제
- **예상 동작:** 기기의 기본 상태 표시줄(상단) 및 홈 조작 바(하단)와 앱 화면이 겹치지 않고 적절한 여백을 가져야 함.
- **실제 동작 (문제점):** 앱의 전체 화면 표시가 너무 높아서 상/하단 기기 기본 영역과 UI가 겹쳐 터치 및 조작이 불편함.
- **원인 분석:** 
  1. 상단: 앱의 글로벌 컨테이너 스타일(`ui.js`의 `page`, `whitePage` 등) 혹은 각 스크린에 상태 표시줄(Status Bar) 영역을 고려한 `paddingTop`이나 `SafeAreaView` 처리가 누락되어 있음.
  2. 하단: `RootNavigator.js`의 하단 탭 바(Bottom Tab Bar) 스타일에 기기 하단 네비게이션 바를 고려한 `paddingBottom` 및 높이(`height`)가 충분하지 않음.
- **수정 계획:**
  1. **상단 여백:** `front/src/styles/ui.js` 파일에서 `page` 및 `whitePage` 스타일에 기기 상단 상태 표시줄의 높이를 반영할 수 있도록 `paddingTop`을 추가 (Android/iOS 환경에 맞게 추가 여백 부여).
  2. **하단 여백:** `front/src/navigation/RootNavigator.js` 내 하단 탭 바의 `paddingBottom` 및 `height`를 늘려 기기의 기본 하단 조작계와 탭이 겹치지 않도록 높이를 상향 조정.

### 2.11. 지도(Map) 하단 목록 클릭 시 동작 분리 (지도 이동만 수행)
- **예상 동작:** 지도의 마커를 직접 클릭했을 때는 상세 정보창(바텀 시트)이 나타나고 해당 위치로 지도가 이동해야 하지만, 하단의 핀 목록 카드를 클릭했을 때는 상세 정보창은 열리지 않고 지도의 중심 좌표만 해당 핀의 위치로 이동해야 함.
- **실제 동작 (문제점):** 하단 목록의 카드를 클릭했을 때도 상세 정보창이 불필요하게 열려 화면을 가려버림.
- **수정 계획:** `MapScreen.js`의 `handlePinPress` 함수(하단 목록 클릭 핸들러)에서 `setSelectedPin(pin)` 호출을 제거하고, 열려있는 팝업을 닫기 위해 `setSelectedPin(null)`을 호출한 뒤 `setCenter`로 지도 이동만 수행하도록 로직 수정.

### 2.10. 지도(Map) 화면 확대/축소 및 내 위치 이동 버튼 미작동 문제 수정
- **예상 동작:** 지도 우측의 `+`(확대), `-`(축소) 버튼 및 '내 위치' 버튼 클릭 시 지도가 정상적으로 확대/축소되거나 내 위치(또는 기본 위치)로 이동해야 함.
- **실제 동작 (문제점):** 해당 버튼들을 눌러도 아무런 반응이 없음.
- **원인 분석:** `MapScreen.js`에서 `<MapMapControls>` 컴포넌트로 전달하는 props의 이름(`onPressZoomIn`, `onPressZoomOut`, `onPressMyLocation`)과 `MapMapControls.js` 컴포넌트 내부에서 받아 사용하는 props의 이름(`onZoomIn`, `onZoomOut`, `onMyLocation`)이 서로 다르게 매핑되어 있어 이벤트 연결이 끊어진 상태였음.
- **수정 계획:** `MapScreen.js`에서 `<MapMapControls>` 호출 시 props 이름을 자식 컴포넌트가 기대하는 `onZoomIn`, `onZoomOut`, `onMyLocation`으로 변경하여 정상적으로 이벤트가 발생하도록 수정.

### 2.9. 지도(Map) 화면 Pin 선택 시 1~2초 딜레이 및 전체 리로드 문제 해결
- **예상 동작:** 지도 마커(Pin) 또는 하단 목록 선택 시 지연 없이 즉시 상세 정보창이 슬라이드업 되고 지도가 해당 마커 위치로 부드럽게 이동해야 함.
- **실제 동작 (문제점):** 
  - Pin 선택 시 화면 갱신까지 1~2초가량의 심한 딜레이가 발생함.
  - 클릭 시 맵이 새로고침(리로드)되면서 기존에 이동했던 위치나 줌 상태가 초기화됨.
- **원인 분석:** 
  1. `MapScreen.js`에서 `<KakaoMapWebView>`에 `center` props를 전달할 때 매 렌더링마다 새로운 객체(`center={{ lat: DEFAULT_LOCATION.lat, lng: DEFAULT_LOCATION.lng }}`)를 생성하여 전달하고 있었음.
  2. `selectedPin` 상태가 바뀌어 화면이 리렌더링될 때마다 `center` 객체의 참조값이 변경되므로, `KakaoMapWebView.js` 내부의 `useMemo`가 새 HTML을 생성해버리고 결과적으로 WebView 전체가 다시 로드되는 심각한 렌더링 성능 이슈가 발생함.
- **수정 계획:**
  1. **불필요한 리렌더링 방지:** `MapScreen.js`에서 새로운 객체 대신 기존 `DEFAULT_LOCATION`을 그대로 전달(`center={DEFAULT_LOCATION}`).
  2. **안전장치 추가:** `KakaoMapWebView.js`의 HTML 생성 `useMemo` 의존성 배열에 객체 대신 원시 값(`center?.lat`, `center?.lng`)을 넣도록 변경.
  3. **지도 이동 동기화:** 지도 핀을 직접 클릭했을 때(`handleMarkerPress`)도 목록을 클릭했을 때처럼 해당 핀 위치로 지도가 이동(`mapRef.current.setCenter`)하도록 로직 추가.

### 2.8. 지도(Map) 화면 Pin 상세 정보창 바텀 시트(Bottom Sheet) 스타일로 디자인 변경
- **예상 동작:** 상세 정보창이 작은 팝업 형태가 아니라 가로로 화면을 꽉 채우고(width 100%), 상단 모서리만 둥근 카카오맵의 장소 정보창(바텀 시트)과 같은 디자인으로 표시되어야 함. 상단에 드래그 핸들(Drag Handle) 시각적 요소가 포함되어야 함.
- **실제 동작 (문제점):** 기존 상세 정보창(`postPreviewCard`)은 `width: 250`으로 작은 카드 형태였고, 상하단 모두 모서리가 둥글게 처리되어 화면 중앙/하단에 작게 떠 있었음. 
- **수정 계획:** 
  1. `styles/map.js` 내 `popupOverlay`의 좌우 여백(padding)을 제거하여 화면 끝까지 닿게 수정.
  2. `postPreviewCard`의 너비를 `100%`로 변경하고, 하단 모서리 둥글기를 제거(`borderTopLeftRadius`, `borderTopRightRadius`만 적용).
  3. `MapPostPreviewCard.js`의 최상단에 바텀 시트 특유의 드래그 핸들 바(회색의 둥근 막대기) UI를 추가.

### 2.7. 지도(Map) 화면 Pin 상세 정보창(미리보기) 슬라이드 애니메이션 및 UI 개선
- **예상 동작:** 
  1. 지도나 목록에서 핀을 선택했을 때, 상세 정보창이 아래에서 위로 부드럽게 슬라이드하며 나타나야 함.
  2. 상세 정보창을 닫을 때 다시 아래로 슬라이드하며 사라져야 함.
  3. 상세 정보창이 나타나도 하단의 핀 목록은 숨겨지지 않고 유지되며, 상세 정보창이 핀 목록보다 상위 레이어에 표시되어야 함.
- **실제 동작 (문제점):** 
  - 핀 선택 시 상세 정보창이 애니메이션 없이 즉시 표시/숨김 됨.
  - 상세 정보창이 표시될 때 하단 핀 목록이 사라짐.
  - 상세 정보창 뒤에 반투명한 어두운 배경이 깔려서 부자연스러움.
- **수정 계획:**
  1. **슬라이드 애니메이션 적용:** `MapScreen.js`에서 `Animated`를 사용하여 `selectedPin` 상태 변화에 따라 상세 정보창(`MapPostPreviewCard`)이 `translateY` 값 변경을 통해 슬라이드 업/다운 되도록 구현. 닫힐 때 애니메이션이 끝난 후 언마운트되도록 `displayPin` 상태 추가.
  2. **목록 유지 및 레이어 겹침 처리:** 하단 핀 목록(`ScrollView`)의 렌더링 조건에서 `!selectedPin`을 제거하여 항상 보이게 유지. `styles/map.js`에서 `popupOverlay`의 배경색을 제거하고 `zIndex: 100`을 부여하여 목록보다 위에 뜨도록 함. 이벤트가 목록/지도로 통과되도록 `pointerEvents="box-none"` 추가.

### 2.6. 지도(Map) 화면 첫 오픈 시 지연 로딩(나중에 갱신) 문제 및 더미 데이터 정리
- **예상 동작:** 
  1. 지도 화면 오픈 시 pin 데이터를 먼저 로딩한 후 지도가 그려져, 처음부터 핀이 정상적으로 표시되어야 함.
  2. 개발 초기에 사용했던 지도 핀 더미 데이터는 더 이상 사용되지 않도록 완전히 삭제.
- **실제 동작 (문제점):** 
  - 지도가 먼저 빈 상태로 그려지고, 이후에 데이터 로딩이 완료되어 지도가 다시 갱신됨 (나중에 깜빡이며 나타남).
  - `config/map.js` 파일 등에 하드코딩된 `MAP_PINS` 더미 데이터가 잔존.
- **원인 분석:** 
  1. `MapScreen.js`에서 비동기로 데이터를 불러오는 동안 초기 상태(빈 배열 `[]`)로 `<KakaoMapWebView>`가 바로 렌더링되어버림.
  2. 임시로 구성해두었던 파일들이 제대로 정리되지 않음.
- **수정 계획:**
  1. **초기 로딩 동기화:** `MapScreen.js`에 `dataLoading` 상태를 추가하고, 데이터 fetch 완료 후(`!dataLoading`일 때만) `<KakaoMapWebView>`를 렌더링하도록 조건부 처리.
  2. **더미 데이터 삭제:** `config/map.js`에서 `MAP_PINS` 삭제. `api/mapApi.js` 및 `services/mapService.js`에서 관련 참조 및 불필요한 고정 데이터 반환 로직을 제거/수정.

### 2.5. 지도(Map) 화면 핀 카테고리 필터 및 하단 목록 UI/UX 개선
- **예상 동작:** 
  1. 화면 좌측 상단에 카테고리 필터(드롭다운 형태)가 있어 '전체' 및 특정 카테고리를 선택할 수 있어야 함.
  2. 선택한 카테고리에 해당하는 핀만 지도와 목록에 표시되어야 함.
  3. 핀 목록은 화면 상단이 아닌 하단에 표시되어야 함.
  4. 핀 목록에서 혹은 지도에서 특정 핀을 선택(클릭)하면 핀 목록은 숨겨지고 해당 핀의 상세 정보 창이 표시되어야 함.
  5. 상세 정보 창을 닫으면 다시 하단 핀 목록이 표시되어야 함.
- **실제 동작 (문제점):** 
  - 현재 카테고리 필터 기능이 없음.
  - 핀 목록이 상단(`top: spacing.lg`)에 고정되어 표시됨.
  - 핀을 선택하여 상세 정보(미리보기 카드)가 팝업으로 떠도 핀 목록이 계속 화면에 남아 있어 UI가 겹치거나 지저분함.
- **수정 계획:**
  1. **필터 드롭다운 추가:** `MapScreen.js` 상단 좌측(`position: absolute`)에 `<Picker>` 혹은 커스텀 드롭다운을 추가하고, `CATEGORY_OPTIONS`를 활용해 카테고리를 선택할 수 있게 상태(`selectedCategory`) 구현.
  2. **필터링 적용:** `pins` 배열을 `selectedCategory`에 맞게 필터링한 `filteredPins`를 지도와 목록에 전달하도록 수정.
  3. **목록 하단 이동 및 조건부 렌더링:** `map.js` 스타일에서 `pinListScroll`의 `top`을 제거하고 `bottom` 속성 부여. `MapScreen.js`에서 `!selectedPin`일 때만 핀 목록 스크롤뷰가 렌더링되도록 조건부 처리.

### 2.12. 지도(Map) 화면 식당(Restaurant) 마커 상세 정보창 UI 보강 (API 미구현 대응)
- **예상 동작:** 식당 마커를 선택했을 때 보여지는 팝업에 별점(하드코딩), 시그니처 메뉴(데이터 기반 조건부 렌더링), 상세 메뉴 목록 안내(하드코딩) 영역이 추가되어야 함.
- **실제 동작 (문제점):** 식당 마커 정보에 식당 관련 UI 영역(별점 등)이 없고, 향후 메뉴 정보 등 확장될 데이터에 대한 레이아웃이 준비되지 않음.
- **수정 계획:**
  1. **식당 구분 조건부 UI 렌더링:** `MapPostPreviewCard.js`에서 선택된 핀이 식당(`post.type === "restaurant"`)일 때 아래 요소들을 순서대로 표시.
  2. **별점 표시:** "⭐ 별점: 3.0 / 5.0 (임시)" 형태의 고정 텍스트 영역을 추가. (추후 API 연동 시 변수 처리)
  3. **시그니처 메뉴 표시:** 기존에 구현한 `post.signature_menu` 영역을 별점 밑에 배치. (데이터가 있을 때만 렌더링)

### 2.13. 지도(Map) 화면 카테고리별 마커 아이콘 차별화 (음식점, 카페 등)
- **예상 동작:** 지도상에서 마커가 단순히 `post` 스타일로 통일되지 않고, 카테고리(식당, 카페 등)에 맞는 고유한 아이콘과 색상으로 렌더링되어야 함.
- **실제 동작 (문제점):** `KakaoMapWebView.js`에서 마커를 그릴 때 `restaurant` 타입의 경우 카테고리(`category`) 구분 없이 단일 스타일로 처리되거나 기본값으로 fallback 됨.
- **수정 계획:**
  1. `front/src/config/map.js` 내 `PIN_STYLES`에 `restaurant` 및 `cafe` 객체를 추가하여 색상, 아이콘 URL, 이모지를 지정.
  2. `KakaoMapWebView.js`에서 핀 데이터를 넘길 때 `category` 필드를 함께 전달.
  3. 지도 HTML 스크립트 단에서 `p.category`를 체크해 "카페"일 경우 `cafe` 스타일을, 그 외 식당일 경우 `restaurant` 스타일을 적용하도록 로직 보강.

### 2.14. 지도 마커 아이콘 디자인 통일 및 변경 (플랫 스타일)
- **예상 동작:** 지도상에서 나타나는 마커(핀) 아이콘들이 통일성 있는 깔끔한 플랫(Modern Flat) 디자인으로 렌더링되어야 함.
- **실제 동작 (문제점):** 기존에 사용된 Flaticon 이미지들의 스타일(3D, 단색 선 등)이 혼재되어 있어 통일감이 부족하고 시각적으로 어울리지 않았음.

  1. `front/src/config/map.js` 내 `PIN_STYLES`의 `iconUrl` 값들을 전체적으로 일관성 있는 플랫 디자인의 이미지 주소로 교체함. (게시글: 문서, 식당: 식기, 카페: 커피잔, 커뮤니티: 그룹, 추천: 별)

### 2.15. 내 현재 위치 표시 핀 (마커) 추가
- **예상 동작:** 지도 화면에 사용자의 현재 위치를 나타내는 파란색 점 모양의 마커가 항상 표시되어야 함. 카카오맵의 내 위치 스타일과 동일한 디자인이 적용되어야 함.
- **실제 동작 (문제점):** 기존 지도에는 내 위치를 나타내는 마커가 표시되지 않았음. (기기 위치 권한 연동 전)
- **수정 계획:**
  1. 기기 위치 연동 전이므로 `config/map.js`의 `DEFAULT_LOCATION`을 임시 현재 위치로 사용하도록 설정.
  2. `KakaoMapWebView.js`에서 `currentLocation` props를 받아 파란색 점(`14px`)과 반투명 파란색 영역(`24px`)으로 구성된 HTML/CSS 마커(`CustomOverlay`)를 그려 지도에 상시 표시.
  3. `MapScreen.js`에서 `currentLocation={DEFAULT_LOCATION}`을 주입하여 지도 호출.
