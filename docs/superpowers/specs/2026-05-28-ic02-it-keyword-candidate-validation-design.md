# IC02 IT 키워드 후보군 검증 설계

## 목적

IC02 IT 뉴스 키워드 추출에서 작은 로컬 LLM이 본문에 없는 조합어를 만들어 `analysis.keywords`에 저장하는 문제를 막는다.

현재 운영 환경은 큰 모델을 안정적으로 올리기 어렵다. 따라서 모델 크기 확장 대신 KiWi 기반 NLP 후보군을 먼저 만들고, LLM은 그 후보군 안에서만 키워드를 선택하게 한다. 저장 직전에도 같은 후보군으로 검증해 원문 근거가 약한 키워드를 버린다.

이 설계는 기존 IC01 맛집 감성 분석과 BERT 키워드 추출을 변경하지 않는다.

## 문제 진단

현재 IC02 키워드 추출은 LLM 응답을 `normalize_it_keywords`로 공백 정리와 중복 제거만 한 뒤 저장한다.

그 결과 작은 모델이 다음과 같은 키워드를 만들 수 있다.

- `Git 레미트리치닝`
- `박스크립트 시스템`
- `이해 필요`

이런 값은 본문 핵심을 반영하지 못하거나, 원문에 없는 조합어이며, downstream 게시글 품질에 직접적인 타격을 준다.

## 범위

포함한다.

- `ai/post_analysis` 내부 IC02 키워드 추출만 변경한다.
- KiWi 기반 후보 추출을 IC02 전용 helper로 추가한다.
- 후보군과 후보 점수는 deterministic 로직으로 만든다.
- LLM prompt에 후보군을 전달하고 후보군 밖 키워드 생성을 금지한다.
- LLM 응답은 저장 전 후보군과 다시 대조한다.
- 후보군 검증 후 유효 키워드가 부족하면 후보군 기반 재요청 또는 deterministic 후보 보강만 허용한다.
- `kiwipiepy` 의존성을 `ai/post_analysis/requirements.txt`에 추가한다.

포함하지 않는다.

- `etl/it_news` 크롤링, cleaning, save 변경
- `etl/meal` 변경
- IC01 `get_reviews`, `analyze_sentimental`, `analyze_keywords` 동작 변경
- `ai/postmake_pipeline` 변경
- DB 스키마 변경
- 큰 LLM 모델 사용을 전제로 한 품질 개선

## 핵심 원칙

키워드는 함부로 혼합하지 않는다.

최종 저장 키워드는 다음 중 하나여야 한다.

- 본문 또는 제목에 실제로 등장한 연속 표면형
- KiWi 후보 추출기가 본문 연속 토큰에서 만든 명사구
- 영문 기술명, 제품명, 버전명처럼 원문에 그대로 등장한 표면형

다음은 저장하지 않는다.

- 원문에 없는 새 조합어
- 서로 떨어진 단어를 LLM이 임의로 붙인 표현
- 의미가 일반적이거나 게시글 신호가 약한 단어
- 깨진 번역어 또는 비정상 음역어
- 한 글자 키워드
- 조사, 어미, 감탄사, 접속 표현

## 후보 추출

후보 추출 입력은 `title + compressed_content`를 기준으로 한다. `compressed_content`는 기존 전처리 검증을 통과한 원문 발췌문이다.

KiWi 분석 결과에서 다음 품사를 후보 재료로 사용한다.

- 명사: 일반명사, 고유명사
- 외국어 및 기술 표기: 영문 토큰, 숫자 토큰
- 어근성 기술 표현: 단독으로 기술 의미가 있는 경우만 사용
- 동사, 형용사: 최종 키워드가 아니라 점수 신호로만 사용

후보는 연속된 후보 재료 토큰으로 만든다. 예를 들어 원문에 `타겟 리모트로 ref와 오브젝트를 직접 스트리밍`이 있으면 `타겟 리모트`, `ref`, `오브젝트`, `직접 스트리밍` 후보는 만들 수 있지만, 원문에 없는 `타겟 리먼트 관리`는 만들 수 없다.

후보 추출 함수는 다음 계약을 가진다.

```text
extract_it_keyword_candidates(title, content) -> list[ItKeywordCandidate]
```

`ItKeywordCandidate`는 최소한 다음 값을 가진다.

- `text`: 최종 후보 문자열
- `score`: deterministic 중요도 점수
- `source`: `title`, `content`, `both` 중 하나
- `frequency`: 후보 등장 횟수

## 후보 점수

후보 점수는 LLM 없이 계산한다.

가점 기준:

- 제목에 등장한다.
- 본문 앞부분에 등장한다.
- 여러 번 등장한다.
- 영문 대문자, 숫자, 버전, 하이픈 등 기술명 패턴을 포함한다.
- `AnalyzeItKeywordsConfig.IMPORTANT_TERMS`와 겹친다.
- 같은 문장 또는 가까운 위치에 변화 동사나 효과 형용사가 있다.

변화 동사와 효과 표현은 최종 키워드가 아니라 점수 신호다. 예시는 다음과 같다.

```text
개선, 지원, 공개, 변경, 삭제, 검증, 자동화, 최적화, 절감, 통합, 배포, 확장
```

감점 기준:

- 너무 일반적인 단어다.
- 한 글자다.
- 숫자만 있다.
- 불용어 목록에 있다.
- 원문 내 표면형 근거가 불분명하다.
- 후보 길이가 과도하게 길다.

불용어와 점수 가중치는 `AnalyzeItKeywordsConfig`에 둔다.

## Prompt 변경

`build_it_keyword_prompt`는 기존 `[compressed_content]`와 함께 `[candidate_keywords]`를 포함한다.

LLM에는 다음 규칙을 명시한다.

- `candidate_keywords` 안에 있는 문자열만 `keywords`에 넣는다.
- 후보군에 없는 새 키워드를 만들지 않는다.
- 후보 여러 개를 임의로 합쳐 새 표현을 만들지 않는다.
- 원문에 없는 번역어, 음역어, 요약어를 만들지 않는다.
- 후보군에서 기술 주제와 게시글 관점을 균형 있게 선택한다.

후보군은 점수 상위 N개만 prompt에 넣는다. N의 기본값은 config로 관리한다.

## 저장 전 검증

LLM 응답은 저장 전에 후보군과 다시 대조한다.

검증 함수 계약:

```text
filter_it_keywords_by_candidates(keywords, candidates) -> list[str]
```

규칙:

- 후보군에 없는 키워드는 제거한다.
- 대소문자 차이, 앞뒤 공백, 중복 `#`만 정규화한다.
- 후보 문자열을 새로 조합하지 않는다.
- 원래 후보 순위와 LLM 응답 순서를 함께 고려하되, 중복은 제거한다.
- 최종 저장 형식은 기존처럼 `#keyword1#keyword2`다.

1차 LLM 응답을 검증한 뒤 유효 키워드가 `MIN_KEYWORDS`보다 적으면 후보군 제한 규칙을 포함해 1회 재요청한다.

재요청 후에도 부족하면 deterministic 후보 상위 항목으로만 보강할 수 있다. 이 보강은 원문 후보군 안에서만 수행한다. 원문에 없는 키워드는 어떤 경우에도 저장하지 않는다.

## 의존성

`ai/post_analysis/requirements.txt`에 다음 의존성을 추가한다.

```text
kiwipiepy
```

KiWi 인스턴스 생성 비용이 크면 module-level lazy initializer를 사용할 수 있다. 단, 함수 실행 중 누적되는 mutable 분석 결과 cache는 두지 않는다.

## 오류 처리

KiWi 분석 실패는 해당 row 처리 실패로 기록하고 다음 row로 넘어간다.

후보군이 비어 있으면 LLM을 호출하지 않는다. 해당 row는 저장하지 않고 로그만 남긴다.

LLM이 후보군 밖 키워드만 반환하면 검증 후 빈 결과가 되므로 저장하지 않는다.

## 테스트 설계

추가 테스트 범위:

- KiWi 후보 추출은 본문에 실제 등장한 명사구와 영문 기술명을 후보로 만든다.
- 동사와 형용사는 단독 최종 후보가 아니라 점수 신호로만 사용된다.
- 후보군 밖 LLM 키워드는 저장 전 제거된다.
- `Git 레미트리치닝`, `박스크립트 시스템`, `이해 필요` 같은 원문 밖 또는 저품질 키워드는 제거된다.
- 후보 여러 개를 임의로 합친 LLM 키워드는 제거된다.
- `build_it_keyword_prompt`는 `[candidate_keywords]`를 포함한다.
- prompt에는 후보군 밖 키워드 생성을 금지하는 문장이 포함된다.
- 후보 검증 뒤 유효 키워드가 부족하면 재요청 prompt가 후보군 제한을 유지한다.
- 후보군이 비어 있으면 LLM과 MERGE를 호출하지 않는다.
- 기존 IC01 테스트와 전체 `ai/post_analysis` 테스트가 통과한다.

## 운영 방식

재추출 시 기존 저품질 키워드를 덮어써야 하므로 `overwrite=True` 또는 CLI 옵션 `--overwrite-it-keywords`를 사용한다.

운영자는 전체 435건을 한 번에 돌리지 않고 `max_rows`를 작게 잡아 품질을 확인한 뒤 배치를 확대한다.

## 승인 기준

구현은 다음을 만족해야 완료로 본다.

- `ai/post_analysis` 테스트가 통과한다.
- 후보군 밖 키워드는 저장되지 않는다.
- ID 4, 5에서 관찰된 유형의 깨진 조합어가 필터링되는 테스트가 있다.
- LLM prompt는 후보군 기반 선택으로 제한된다.
- DB merge payload는 계속 `crawling_id`, `keywords`만 포함한다.
- 기존 IC01 맛집 분석 동작은 변경되지 않는다.
