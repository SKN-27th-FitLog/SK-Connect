# 개요
본 문서는 작업의 목표와 방향 및 구현 시 지켜야 할 것들에 대해 가이드 라인을 제시하기 위해 작성된 문서 입니다. 

# 작업 방향
에이전트는 해당 파일의 내용을 프롬프트로 사용해서 작업 방향을 결정하고 이미 작업된 내용에 대해서 검토할 수 있어야 합니다. 
이를 통해 작업의 목표와 방향성을 일정하게 유지하고 일관된 방향으로 유지/보수를 할 수 있도록 합니다. 

## 1. 게시글 수집 
1) 제시된 사이트 들의 게시글 각각을 크롤링 해서 수집합니다. 
 - 수집된 게시글은 LLM이 학습이나 검색 / 추천에 사용할 수 있도록 하기 위해 수집합니다. 
 - 수집된 내용은 다음 내용을 포함해야 합니다. (게시판 마다 다를 수 있음)
    - 필수 = 해당 내용이 필수로 수집되어야 함 -> 없으면 수집 실패 :: [제목], [내용], [주소], [게시글id 또는 고유번호]
    - 선택 = 있으면 수집하고 없으면 값을 0이나 공백으로 처리하고 넘어감 
         :: [댓글 수], [댓글내용], [댓글 작성자 이름], [좋아요 수], [추천 수]
         :: [출처]
   
2) 게시글의 내용을 수집하는데 필수 내용이 하나라도 없으면 수집 실패로 취급
3) 폴더 구조를 통해 해당 일지의 크롤링이 수집됬는지, 수집실패 케이스가 있는지 체크 (파일 내용을 확인 안해도 폴더에 존재 만으로 체크하기 위함 )
4) 수집대상 사이트 별로 python 파일이 하나씩 존재함 
5) 각각의 파일을 실행하면 해당 사이트의 게시글을 수집하는 형태로 작업되어야 한다. 

## 2. 수집된 게시글 전처리 (cleaning data)
1) 일자별로 수집된 개별 파일들을 확인해서 DB의 crawling 테이블 형식에 맞게 슬라이싱 한 다음 저장하는 기능이다. 
2) 1번과 마찬가지로 클리닝에 실패한 파일들을 따로 모아서 재시도 할 수 있도록 해야 한다. 
3) 전처리 시 설정한 컬럼들이 모두 DB에서 허용한 양식으로 맞춰져 채워야 하며 만약 의도한 결과 대로 채우지 못했다면 실패 리스트로 보내야 한다. 
4) 각 스키마에 설정된 컬럼 제한 사항을 지켜야 함 (글자수 슬라이싱, 코드 테이블 값 적용 등...)
5) 전처리 적용 중 실패한 데이터가 있으면 해당 데이터만 따로 모아서 저장해야 한다. (해당 파일이 존재하면 확인해서 재적용 하기 위함 )

## 3. 전처리 완료된 파일 DB에 저장(save data)
1) 전처리 성공한 데이터들만 가져와서 시도한다, 
2) DB에서 데이터 조회 해서 등록된 가장 마지막 일자/시간을 기준으로 해당 시간보다 뒤에 있는 파일 & 폴더명을 가진 데이터들을 적용한다. 
3) 저장되는 데이터는 crawling 테이블과 comment 테이블을 대상으로 해야 한다, (연결된 DB에서 정보를 찾아서 구현해야 함 )
4) 저장은 해당 데이터에 신규 데이터를 추가하는 insert 방식이어야 함
5) 먼저 crawling 데이터 먼저 저장하고 저장한 뒤 해당 데이터의 crawling_id 값을 확보한다 (원래 데이터에는 없는 값인데 등록하면서 생성됨 )
6) 그 뒤 comment 테이블에 데이터를 등록할 때 해당 댓글이 원래 등록되어 있던 게시글의 crawling_id 값을 설정한 뒤 DB에 등록되어야 함

# 코드 및 수집한 데이터 폴더 구조 
- 데이터 처리에 성공한 데이터는 성공 폴더에 넣고 실패한 값들은 실패 폴더로 보낸다. 
- 저장의 경우 쿼리 요청해서 저장하는데 만약 실패한 경우가 발생하면 실패한 파일은 따로 분류해서 나중에 재시도 한다. 

## 1. 수집 폴더 (crawling - 년/월/일은 폴더, 시분초는 파일 이름으로 사용 )
- 수집 성공 : raw/2026/04/19/success/geeknews_011127.csv
- 수집 실패 : raw/2026/04/19/fail/geeknews_030745.csv

## 2. 처리 폴더 (cleaning - 년/월/일은 폴더, 시분초는 파일 이름으로 사용 )
- 처리 성공 : cleaning/2026/04/19/success/geeknews_011127.csv
- 처리 실패 : cleaning/2026/04/19/fail/geeknews_030745.csv

## 3. 저장 폴더 (save - 년/월/일은 폴더, 시분초는 파일 이름으로 사용 )
- 저장 성공 : save/2026/04/19/success/geeknews_011127.csv
- 저장 실패 : save/2026/04/19/fail/geeknews_030745.csv


# 주의사항 : 다음 사항을 주의하면서 계획 및 작업을 진행한다. 
1) 해당 문서 가장 우선순위가 높게 체크한다. 
2) 이전 작업 사항을 확인한다. (작업 내용에 참고하기 위함 )
3) etl / it_news 폴더 안의 데이터만 관리 대상으로 한다. 
4) 수집(crawling) / 처리(cleaning) / 저장(save) 폴더를 각각 루트로 보고 가상환경 생성해서 작업한다. 
5) common 폴더 등 공용 코드는 수집(crawling) / 처리(cleaning) / 저장(save) 폴더 각각에 생성한다. 
6) 수집(crawling) / 처리(cleaning) / 저장(save) 폴더 각각에 requirements.txt 파일 추가해서 가상환경 라이브러리 설정한다. (설정한 라이브러리는 버전 고정한다. )
7) pyhton은 3.13 버전을 사용하고 해당 버전 기준 최신 pip 로 각각의 가상환경을 인스톨해서 작업한다. 
8) 작업 계획과 작업 후 처리한 내용은 각각 별도의 md 파일로 만들어서 사전 / 사후 작업 상황을 체크할 수 있도록 한다. (해당 파일은 etl/it_news/docs에 위치함 )
