# 작업 목표

1) 데이터 수집 함수 
 - 게시판 별로 데이터를 수집하는 함수를 만든다. 
 - 데이터 수집 함수는 내부에 순차적으로 각 게시판 함수를 돌면서 리턴된 값을 데이터 파일에 업데이트 한다. 
 - 순회하면서 데이터 프레임에 누적한 정보들을 최종적으로 하나의 csv 파일로 저장하게 한다. 
 - 저장 파일의 이름은 오늘 날짜 기준으로 작성한다. 
 - 오류 발생하는 경우 수집한 데이터 row에 상태 기록하고 넘어간다. (state 컬럼을 따로 둬야 함)
 - 스키마에 맞춰서 데이터 넣는 것 까지를 각 테이블 함수로 처리한다. 
 - 게시글의 내용을 가져올 때 게시글에 이미지가 있는 경우도 고려해 봐야 함 

2) 데이터 클린징 함수 
 - 수집한 오늘자 데이터를 클린징 하는 함수를 만든다. 
 - 1번에서 수집한 테이블을 가져와서 클린징 처리를 한다. 
 - 클린징 처리를 하다가 문제가 생긴 row가 있으면 해당 row는 드랍한다. (드랍된 row는 별도 테이블 - 오늘 날짜로 기록)

3) 클린징 처리한 데이터를 DB에 저장한다. 
 - 정리된 csv 파일을 DB에 저장하도록 한다. 
 - 저장 실패 시는 실패로 알려준다. (파일 전체가 올라가고 끝으로 처리할거면 그냥 실패로 처리함 )




# 수집 전략

1) 게시글 목록 크롤링 (1차 크롤링)
- 크롤링 시간을 줄이기 위해 주요 게시판 별로 게시글 목록 기준으로 크롤링을 진행한다. 
- 게시글 목록 정보를 기준으로 스키마로 수집할 데이터를 결정한다.
- 각 게시판 별로 항목의 이름이 다르기 때문에 수집할 게시판에 맞춰서 일정 부분 하드코딩으로 처리한다. (정확한 정보 분류를 위해 ...)

2) 게시글 목록 저장
- 수집한 게시글 목록은 "수집한 날짜 + 게시판 이름.csv" 파일로 저장한다. (날짜가 앞인 이유는 )
- csv 파일은 수집이 일어나는 각 폴더에 저장하도록 한다. 
- DB에 올라가는것으로 가정하고 통합 게시글 목록 파일은 별도로 존재한다. (루트 경로에 파일을 둠)
- 각 크롤링 단계 별로 생성된 파일들은 세부 폴더에 각각 위치시킨다. 

3) 게시글 내용 크롤링 (2차 크롤링)
- 게시글의 내용을 게시글 각각을 열어서 업데이트 한다. 
- 모든 게시글의 내용을 업데이트 하진 않고 규칙에 맞춰서 정렬시킨 다음 게시판 별로 약 20개 정도의 글의 내용을 업데이트 한다. 
- 게시글의 내용이 업데이트 되지 않은 정보는 내부적으로만 유지힌다. 
- 게시글의 내용까지 업데이트 된 정보만 실제 사용하는 정보임
